Teste de Estresse — o device sustenta a performance?

Carga contínua por vários minutos. Se a placa esquentar e reduzir o clock (throttling térmico), a performance cai sob uso prolongado — o device pode não servir para aquela carga em produção. As métricas-chave: degradação (queda de throughput ao longo do teste), temperatura máxima e se houve throttling. Um device que segura a performance mantém degradação ~0 e não throttla.

Perfis de Benchmark

Edite os parâmetros dos perfis de benchmark. As alterações são salvas no arquivo config/benchmark.yaml e ficam disponíveis imediatamente para os próximos benchmarks (sem rebuild dos containers).

Parâmetros por seção:
• throughput: duration_sec (duração do teste), warmup (iterações de aquecimento)
• latency: samples (nº de amostras), percentiles (lista: [50,95,99])
• resource_usage: duration_sec, interval_sec (intervalo de coleta)
• sustained_load: duration_min (0 = desabilitado)
• memory_bandwidth: enabled (true/false), patterns, block_sizes_kb

Guia de Configuração

Como funciona

Cada perfil define parâmetros para 5 tipos de teste:

  1. Throughput — Roda inferências continuamente por duration_sec e mede ops/s
  2. Latência — Executa samples inferências individuais e calcula percentis
  3. Uso de recursos — Mede container, processos, host e aceleradores durante a mesma janela de inferência
  4. Carga sustentada — Roda por duration_min minutos medindo degradação (0 = skip)
  5. Bandwidth de memória — Testa largura de banda com padrões sequencial/random

Perfis próprios

Você pode criar perfis novos, alterar parâmetros ou remover seções inteiras. Por exemplo, para criar um perfil "custom":

profiles:
  custom:
    throughput: {duration_sec: 20, warmup: 2}
    latency: {samples: 30, percentiles: [50, 99]}
    resource_usage: {duration_sec: 20, interval_sec: 1}
    sustained_load: {duration_min: 0}
    memory_bandwidth: {enabled: false}

Dispositivo de execução do áudio

Whisper (ASR): usa CTranslate2/CUDA quando o container recebe a GPU e o runtime oferece um tipo de cálculo compatível. Caso contrário, a carga usa CPU e registra esse dispositivo.

Piper (TTS): usa ONNX Runtime em CPU nesta versão, inclusive quando o container de áudio recebe uma GPU.
